# AY-PLAYER SIMPLE: первичный разбор

Исходные файлы оставлены без изменений.

## Что найдено

- `testr.ino`: проигрыватель PSG из корня SD, без дисплея и кнопок. Симптомы устройства совместимы с этой прошивкой, но содержимое Nano пока не прочитано.
- `AY3-8912_14_NANO.ino`: расширенный проигрыватель, OLED SSD1306 128x32, адрес 0x3C, кнопки на аналоговом A6. Ожидает каталоги `/0`, `/1` и далее.
- `LIB/libraries/SSD1306Ascii`: библиотека версии 1.1.3.
- Два скетча в одном каталоге нельзя собирать как один проект: повторяются setup(), loop() и другие определения. Для новых вариантов нужны отдельные каталоги скетчей.

## Подключения по исходникам

| Nano | Назначение |
|---|---|
| D2 | RESET AY |
| D3 | тактовый сигнал AY, Timer2 |
| A0–A3 | младшие биты данных AY |
| D4–D7 | старшие биты данных AY |
| D8 / D9 | BC1 / BDIR |
| D10 | CS SD |
| D11 / D12 / D13 | MOSI / MISO / SCK SD |
| A4 / A5 | SDA / SCL OLED |
| A6 | кнопки через резистивную цепочку |

## Ошибки расширенного скетча

1. `PORTC = ...` перезаписывает весь порт, сбрасывая подтяжки A4/A5. Нужно сохранять верхние биты: `(PORTC & 0xF0) | (value & 0x0F)`. При внешних подтяжках это не обязательно причина тёмного дисплея.
2. `string2char(String command)` возвращает указатель на уничтожаемый локальный String. Использовать устойчивый буфер или c_str() строки, которая живёт во время вызова SD.open().
3. `entr.name()` используется после `entr.close()`. Имя нужно скопировать до закрытия.
4. Переменные, совместно используемые ISR и основным циклом, не volatile; доступ к 16/32-битным значениям не атомарный.
5. `resetAY()` содержит delay() и вызывается при cli(). На AVR ожидание millis() с выключенными прерываниями может зависнуть. Отключать только прерывание проигрывателя, сохраняя Timer0.
6. Циклы ожидания `analogRead(A6)<1000` могут навсегда блокировать работу при другой резистивной цепочке или плавающем входе. Нужны реальные измерения, антидребезг и неблокирующая обработка.
7. `random(0, count-1)` исключает последний элемент; верхняя граница random() не включается.
8. Счёт файлов включает любые файлы, а каталоги предполагаются числовыми и непрерывными. Нужна фильтрация PSG и обработка пустых каталогов.
9. Поиск первого 0xFF вместо разбора 16-байтного заголовка может потерять первый кадр.
10. OLED перерисовывается слишком часто; блокирующие эффекты кнопок мешают наполнению музыкального буфера.

## Диагностика

`diagnostics/NanoDiagnostics/NanoDiagnostics.ino` сканирует I2C, пробует OLED на 0x3C/0x3D и выводит A6 каждые 200 мс в Serial 9600 и на экран. Держит AY в сбросе, поэтому музыка во время диагностики не играет. Прошивка диагностикой заменит текущую программу; до этого желательно сохранить flash и EEPROM Nano.

Статья https://habr.com/ru/articles/392625/ описывает базовую звуковую часть без готового интерфейса дисплея и кнопок.
